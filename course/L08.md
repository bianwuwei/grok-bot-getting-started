### 第 8 课带走：技能卡模板 + 存技能检查清单

> 出处：Grok Bot 文档 docs.x.ai/grok-bot「Skills, routines, and automations」「FAQ」；界面路径按 2026-09-30 录课时的 Grok Bot 桌面版实机。标「观察」的是录课时看到的现象，文档没有写。

#### 1. 该不该存成技能

先做一次 → 做稳 → 存成技能 → 最后才自动化（定时任务是第 11 课）。

**适合存（三个信号）**
- 同一类活做过两三次，每次都在交代同样的要求
- 做法已经稳定，验收过，结果靠得住
- 换个 Bot、换份材料，做法不变

**先别存**
- 只做一次的活
- 做法还在改，每次结果不一样
- 每一步都得你临场拍板

**技能 vs 定时任务**：技能写「怎么做」；定时任务写「交给哪个 Bot、什么时候做」。先在一次真活上把技能测稳，再交给定时任务。

#### 2. 技能卡六格（空白模板）

存技能时整段发给 Bot：「把刚才这套做法存成一个技能，名字叫 ____，写清楚下面六件事。」

| 格 | 写什么 | 你的内容 |
| --- | --- | --- |
| ① 什么时候用 | 遇到什么材料／请求时用 | |
| ② 需要什么 | 必需输入、可选输入、需要的连接或登录 | |
| ③ 步骤 | 按顺序写 | |
| ④ 交之前自查 | 怎样算合格 | |
| ⑤ 交回什么 | 格式、放在哪（聊天里还是文件） | |
| ⑥ 哪些事先问我 | 发消息、删除、花钱等（见第 9 课） | |

#### 3. 今天的实例：演示-周报三段式

- 真活：演示-小派把一周流水账（演示数据）整理成三段式周报——①本周做成了什么 ②卡住了什么、卡在谁 ③下周要做什么（每条负责人）；没写负责人的标「待确认」，每段 ≤3 条，只在聊天里回。
- 存：「这版可以。把刚才这套做法存成一个技能，名字叫「演示-周报三段式」。写清楚：什么时候用、需要我给什么、按什么步骤做、交之前怎么自查、交回什么样子、哪些事要先问我（比如发给别人）。」
- 六格都写进去了；「先问我」一格写的是：发给任何人、转到群里或写进别的文档之前必须先问。

#### 4. 存、找、用、改

| 步骤 | 怎么做 |
| --- | --- |
| 存 | 在对话里说：「把我们刚才用的流程存成一个技能，名字叫 ……」 |
| 找 | 侧栏底部 **Plugins** → 顶部「… installed · … private」那行 → **Private**（文档写作 Marketplace → Your plugins → Manage plugins and skills → Private skills；中文界面是：连接应用 → 市场 → 已安装 N 个 → 管理插件和技能 → 私有技能） |
| 用 | 输入框打 **/** 和技能名前几个字 → 选中（出现技能标签）→ 接上这次的材料 → 发送。技能在你所有的 Bot 之间共用（我们在演示-小试里调用了演示-小派存的技能） |
| 改 | Private → 点技能名 → 改 Name／Description／Instructions → **Save**（变成 Saved）。右上角 Publish（往外分享）、Delete Skill（删除）先想清楚再点 |

另：文档还写了「Teach a task」——在电脑画面里录一段浏览器操作（最长 10 分钟），生成技能草稿再检查测试；功能逐步开放，本课未演示。

#### 5. 改完要验证

- **观察**：改完技能后，在同一个对话里只口头说「按演示-周报三段式整理一下」，Bot 仍按旧版做；第二次用 **/** 选中技能，并加了一句「按技能最新版本来，先重新读一遍」，再发同一份材料，新加的「要我拍板」一行才出现。两样一起用，分不清是哪一样起的作用。
- 规矩：改完用 **/** 选中技能，并说明按最新版重读，再调用一次，对照改动那一处检查（第 4 课验收的习惯）。

#### 本周就做
1. 找一件你交代过三次的活
2. 做一次、验收，再一句话存成技能
3. 换一个 Bot，用 / 调用一次
